# 实施路线与验收

## 1. 总体路线

采用“离线数据 → 被动记牌 → 实时建议 → 监督执行 → 受控自动化”的顺序。后一个阶段必须建立在前一阶段的可重复验收结果上。

单人开发的可靠 MVP 预计需要 14–22 周。时间取决于日志覆盖度、首个卡组的复杂度、规则模拟范围和画面识别稳定性。

## 2. 阶段计划

### P0：项目基础与技术验证（1–2 周）

交付：

- 产品需求、架构、领域模型、决策与风险文档。
- Git 规范、目录规划和设计变更流程。
- 日志读取、窗口捕获、普通输入、OpenAI 兼容接口的最小技术验证报告。
- 确认首个客户端语言、模式、卡组和目标分辨率。
- 数据源许可及更新方式记录。

退出条件：

- 能从一段真实且脱敏的日志识别对局开始、回合和基础实体事件。
- 能可靠识别目标游戏窗口，但不进行自动操作。
- 明确最终技术栈和不支持范围。

### P1：卡牌、卡组与版本数据（2–3 周）

交付：

- 卡牌数据导入、校验和版本化快照。
- 卡组代码导入、规范化哈希和用户卡组选择。
- 结构化效果标签的第一版覆盖。
- 一个主流卡组数据源适配器及每日不可变快照。
- 数据差异和补丁更新报告。

退出条件：

- 指定版本的首个己方卡组能够完整解析。
- 历史卡牌快照不受新同步覆盖。
- 数据源失败时保留并标记最近有效快照。

### P2：事件流与被动状态追踪（3–4 周）

交付：

- 增量日志读取、轮转恢复和规范事件协议。
- 事件归约器、状态快照及离线重放工具。
- 己方卡组、手牌、牌库、场面和使用历史追踪。
- 生成、发现、复制、偷取、变形和洗入来源链。
- 对局记录和基础记牌器界面。

退出条件：

- 黄金回放样本中的关键状态准确率达到 99% 以上。
- 事件缺口和未知事件不会静默生成伪状态。
- 整场对局可从事件流重建并得到相同结束结果。

### P3：对手原型识别与日报（2–3 周）

交付：

- 按职业和环境快照建立候选原型。
- 基于展示卡和来源可信度更新候选概率。
- 关键未使用卡牌概率区间。
- 未知卡组记录及离线聚类候选。
- 按职业、原型、先后手生成日报。

退出条件：

- 标注回放集可以测量 Top-1、Top-3 和 Unknown 识别质量。
- 生成牌不会作为强构筑证据。
- 日报可以从相同事实数据重复生成一致结果。

### P4：换牌与实时建议（3–5 周）

交付：

- 首个卡组的策略配置和换牌规则。
- 合法原子动作生成器。
- 确定性斩杀检查和有限动作序列搜索。
- OpenAI 兼容模型网关、结构化响应和本地验证。
- 回合建议、候选评分及决策复盘。

退出条件：

- 黄金战术样本中的非法候选和非法最终动作均为零。
- 模型超时、错误格式和候选外输出可以安全回退。
- 常规建议 P95 不超过约定时间预算。
- 人工复核能够看懂每次决定的状态、候选和理由。

### P5：监督执行（3–4 周）

交付：

- 窗口校准、卡牌/目标定位和高层动作映射。
- 用户确认后执行的监督模式。
- 动作前置检查、执行后确认、超时和状态漂移处理。
- 全局暂停、人工接管和紧急停止。
- 发现、目标选择、攻击和结束回合的受控支持。

退出条件：

- 练习或友谊赛中连续完成约定数量的受控测试局。
- 错误窗口输入为零，非法游戏动作输入为零。
- 任何识别失败或失焦都会停止，而不是盲目重试。

### P6：受控自动流程与运行维护（2–4 周）

交付：

- 自动进入受支持对局后的换牌、回合和结束闭环。
- 启动前检查、运行健康状态和崩溃恢复。
- 补丁变化检测、规则覆盖门槛和自动降级。
- 运行成本、异常率、人工接管率和数据质量报告。

退出条件：

- 只在明确允许的受控环境通过长时间稳定性测试。
- 重启后默认回到建议模式，不自动恢复输入。
- 未识别补丁、卡牌或窗口布局会锁定自动执行。

### P7：持续扩展

- 增加己方卡组原型和职业策略。
- 增加客户端语言、分辨率和合法游戏模式。
- 提高复杂规则覆盖、搜索效率和对手响应建模。
- 建立策略版本 A/B 离线评估和长期统计。
- 根据服务条款、维护成本和风险评估决定是否扩大运行范围。

## 3. 优先级

### Must

- 状态事件流、版本化卡牌数据、卡组导入。
- 合法动作校验、状态漂移停止、全局紧急停止。
- OpenAI 兼容配置和密钥保护。
- 对手候选、记牌、对局记录及基础日报。
- 一个卡组的换牌和回合建议。

### Should

- 多环境数据源、未知卡组聚类、截图诊断开关。
- 监督执行、发现选择和复杂目标支持。
- 模型费用预算和本地确定性回退。

### Could

- 多卡组、多语言和更多模式。
- 可视化复盘、策略对比和局面书签。
- 本地模型、远程只读监控或移动端通知。

## 4. 测试策略

### 单元测试

- 卡组代码、卡牌版本、事件解析和状态归约。
- 卡牌来源链和多重集合计算。
- 对手概率更新与未知原型门槛。
- 合法动作、目标选择和资源约束。
- 报告聚合、样本数和置信区间。

### 黄金回放测试

保存脱敏、可公开且版本明确的最小事件样本，并配套人工确认状态。每次规则或解析器修改都重放全部样本，检测状态差异。

### 战术局面测试

构造首个卡组的：

- 确定性斩杀。
- 多种出牌顺序。
- 满场、满手和资源边界。
- 嘲讽、冻结、免疫、潜行和目标限制。
- 发现、随机结果和生成牌。
- 对手关键响应牌概率差异。

### 集成测试

- 模型正常、超时、限流、错误 JSON 和能力不兼容。
- 日志轮转、截断、延迟、重复和乱序。
- 游戏窗口失焦、缩放变化、遮挡和弹窗。
- 数据库迁移、损坏恢复和数据源不可用。

### 受控端到端测试

只在练习或双方知情的友谊赛中进行。逐步从观察、建议、单动作确认提升到完整监督执行，每一级都要达到错误率门槛。

## 5. 关键指标

| 类别 | 指标 | MVP 目标 |
| --- | --- | --- |
| 状态 | 支持事件的解析成功率 | ≥ 99% |
| 状态 | 黄金回放关键字段准确率 | ≥ 99% |
| 安全 | 非法最终动作率 | 0 |
| 安全 | 错误窗口输入 | 0 |
| 执行 | 受支持动作确认成功率 | ≥ 99% |
| 时延 | 常规决策 P95 | ≤ 3 秒，最终以技术验证为准 |
| 时延 | 复杂决策 P95 | ≤ 8 秒，保留执行安全时间 |
| 稳健 | 关键状态低置信时停止率 | 100% |
| 推断 | 原型 Top-1 / Top-3 准确率 | 建立基线后设门槛 |
| 推断 | 非主流卡组拒识能力 | 单独报告，不能强制归类 |
| 运维 | 模型失败后的安全回退率 | 100% |

胜率、段位和每日对局量是结果指标，不作为放宽安全门槛的理由。

## 6. 发布门槛

| 级别 | 允许能力 | 必须满足 |
| --- | --- | --- |
| R0 | 离线数据和回放 | 数据版本化、测试样本可重放 |
| R1 | 实时观察 | 不产生输入，状态质量可见 |
| R2 | 实时建议 | 合法性测试通过，模型输出受约束 |
| R3 | 用户确认后单步执行 | 窗口校验、前后置确认、紧急停止 |
| R4 | 受控环境连续执行 | 稳定性、漂移停止和异常恢复通过 |
| R5 | 扩大运行范围 | 重新进行条款、风险和数据质量评审 |

## 7. 编码前的下一步

1. 选择一个具体的标准卡组作为首个支持对象。
2. 确认客户端语言、Windows 版本、窗口模式和缩放设置。
3. 收集一份脱敏 `Power.log` 和对应人工对局时间线作为首个黄金样本。
4. 确认卡牌与主流卡组数据源的授权和访问方式。
5. 完成 .NET、窗口捕获、日志监听和普通输入的技术验证。
6. 将技术栈和关键选择写成 ADR 后，再开始正式业务代码。
