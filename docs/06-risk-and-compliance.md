# 风险、合规与运行边界

## 1. 基本立场

项目的技术研究目标不代表游戏运营方允许无人值守参与公开匹配。开发和每次扩大运行范围前，都应检查当时有效的暴雪最终用户许可协议、服务条款和游戏规则。

账号处罚、环境公平性及服务条款风险不能通过技术手段消除。项目不提供反检测、行为伪装或绕过安全机制的设计。

## 2. 允许的工程边界

- 读取用户本机可访问且获准使用的游戏日志。
- 捕获用户明确选择的游戏窗口画面。
- 使用本地卡牌数据和获得许可的公开数据源。
- 通过正常操作系统输入接口，在受控测试环境执行动作。
- 提供观察、建议、人工确认和紧急停止。
- 保存经过脱敏、具有明确保留周期的诊断数据。

## 3. 不纳入项目的能力

- 注入游戏进程、读取或修改游戏内存。
- 拦截、修改或伪造客户端网络通信。
- 绕过反作弊、安全校验、速率限制或访问控制。
- 检测反作弊后隐藏进程、随机化行为以规避识别。
- 使用盗取、购买或未经允许共享的账号数据。
- 绕过网站访问限制抓取主流卡组数据。
- 在用户未明确启用时自动排队或恢复输入。

## 4. 运行模式安全门槛

### 观察模式

只读取状态和记录，无客户端输入。日志解析不完整时仍可运行，但必须展示数据质量。

### 建议模式

只有在卡牌、规则和状态版本兼容时才显示可执行建议。未知交互可以显示分析，但需标注“不支持自动执行”。

### 监督执行模式

要求窗口身份、状态置信度、合法性、执行器校准和紧急停止全部通过。每条动作由用户确认。

### 自动执行模式

除监督模式条件外，还要求受控端到端稳定性测试通过。重启、版本变化、失焦、掉线、状态漂移或用户接管后，必须自动退出到更低模式。

## 5. 风险登记

| 风险 | 可能性 | 影响 | 缓解措施 |
| --- | --- | --- | --- |
| 无人值守游戏违反服务条款 | 高 | 账号处罚、项目不可用于目标场景 | 默认建议模式；扩大范围前重新评审；不承诺规避处罚 |
| 游戏补丁改变日志或规则 | 高 | 状态错误、非法建议 | 构建号检查、版本快照、黄金回放、未知版本锁定执行 |
| 日志缺失或乱序 | 中高 | 状态漂移 | 增量偏移、事件重放、置信度、关键状态暂停 |
| 生成牌被误认为构筑牌 | 中 | 对手原型错误 | 实例来源链、低权重证据、Unknown 候选 |
| 复杂卡牌规则未覆盖 | 高 | 搜索结果错误 | 规则覆盖标记、卡牌白名单、建议模式降级 |
| 模型幻觉或格式错误 | 高 | 错误战略或动作 | 结构化候选、协议校验、本地合法性、超时回退 |
| 模型服务泄露对局或身份信息 | 中 | 隐私风险 | 最小上下文、默认不传截图、脱敏、可替换服务 |
| API Key 泄露 | 中 | 费用和账号风险 | 系统凭据存储、环境变量、日志过滤、密钥轮换 |
| 画面缩放或遮挡导致误点 | 中高 | 非预期输入 | 目标窗口校验、视觉置信度、动作前后置条件、立即停止 |
| 输入发送到其他窗口 | 低但严重 | 数据或系统操作风险 | 窗口句柄与前台进程双校验；Input Worker 最小权限 |
| 回合时间内无法完成规划 | 中 | 烧绳或不完整回合 | 时间预算、分级搜索、本地回退、保留执行时间 |
| 环境卡组数据失真或陈旧 | 中 | 推断和策略偏差 | 多源、样本量、陈旧标记、来源审计、Unknown 质量 |
| 抓取数据违反许可 | 中 | 法律和服务风险 | 优先官方/授权 API；保存条款与来源；失败不绕过 |
| 小样本胜率误导优化 | 高 | 策略退化 | 显示样本与置信区间；离线版本比较；禁止即时在线更新 |
| 本地数据库包含隐私数据 | 中 | 隐私泄露 | 数据最小化、保留周期、一键删除、可选加密 |

## 6. 凭据与配置

- 仓库只提交 `.env.example` 或无敏感值的配置模式。
- API Key 使用 Windows Credential Manager、环境变量或同等级凭据存储。
- 日志过滤 `Authorization`、API Key、自定义认证头和查询参数。
- 配置导出默认移除凭据，只保留凭据引用名称。
- 模型服务切换时明确显示数据将发送到哪个地址。
- 第三方服务能力探测不得把真实对局内容作为测试请求。

## 7. 对局与画面隐私

- 默认不保存全屏截图和连续录像。
- 必须截图诊断时只捕获游戏窗口，并提供可见提示。
- 原始日志可能包含账号或本机路径，进入长期存储前先脱敏。
- 上传给模型的数据不包含玩家昵称、BattleTag、本机用户名和绝对路径。
- 未经用户明确选择，不把本地对局数据上传到集中服务或用于训练。

## 8. 数据源合规

每个数据源适配器记录：

- 来源名称、URL 或接口标识。
- 使用条款、许可说明和检查日期。
- 允许的访问频率及缓存要求。
- 抓取字段、数据时间范围和署名要求。
- 适配器版本及失败状态。

如果来源没有公开 API，应优先请求授权或使用允许下载的数据集，不通过代理、验证码绕过或账号轮换继续抓取。

## 9. 安全停止设计

以下任一条件触发立即停止后续输入：

- 全局停止热键或用户点击暂停。
- 游戏窗口不再是预期前台窗口。
- 回合归属、对局阶段或状态版本发生变化。
- 关键状态置信度低于门槛。
- 游戏构建、卡牌快照或规则版本不兼容。
- 动作没有在规定时间产生预期事件。
- 出现未支持的交互、弹窗、掉线或重连。
- Input Worker、核心进程或数据库健康检查失败。

停止后不自动恢复。用户确认问题已解决并重新校验后，才允许重新进入监督或自动模式。

## 10. 上线评审清单

每次提高发布级别前确认：

1. 当前服务条款和目标运行环境已经复核。
2. 新补丁的黄金回放和规则覆盖测试通过。
3. 自动输入错误率、漂移停止和紧急停止达到门槛。
4. 模型服务、数据去向、费用上限和密钥状态明确。
5. 数据源仍可合法使用且没有超过访问频率。
6. 用户能够查看、导出和删除自己的运行数据。
7. 已知风险、未支持卡牌和模式在界面中可见。
8. 回滚到观察/建议模式的方式已经实际验证。
