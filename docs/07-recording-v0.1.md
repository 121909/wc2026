# Windows 被动对局记录器 v0.1

## 1. 版本定位

v0.1 是 Windows WPF 被动记录器的首个可运行骨架。它只观察 Hearthstone 输出的 `Power.log`，把原始证据和可重放的结构化记录保存到本机，不向游戏窗口发送任何输入。

这个版本用于在 Windows 上验证三个问题：

1. 能否稳定发现并增量读取 Hearthstone 日志。
2. 能否识别对局边界并保存不覆盖历史的记录。
3. 能否为后续状态归约、回放和人工复盘提供清晰的文件契约。

它不是完整记牌器，也不包含决策或自动操作能力。

## 2. v0.1 范围

### 包含

- .NET 8、C# 和 WPF 的 Windows 桌面宿主。
- 自动查找默认 `Power.log`，并允许使用本地设置覆盖日志位置。
- 在文件追加时增量读取新行；找不到日志时保持等待并显示状态。
- 从日志行识别最小生命周期和实体事件集合。
- 按会话、对局追加写入原始行、规范事件、状态快照和最终摘要。
- 在界面展示运行状态、当前日志路径、当前对局和基础计数。
- 通过停止监听或关闭应用安全结束本次会话。

### 不包含

- HSReplay、第三方环境数据或账号绑定。
- 屏幕截图、OCR、窗口捕获和画面识别。
- SQLite、云同步或跨机器汇总。
- 完整卡牌数据库、卡组代码导入和来源链推断。
- 对手卡组识别、策略建议、模型调用或日报。
- 鼠标、键盘、进程注入、内存读取或任何游戏控制。
- 生产级日志语法覆盖和补丁兼容保证。

## 3. 记录架构

```text
Power.log
   │  增量读取
   ▼
日志跟随器 ──► 原始行记录 raw-lines.jsonl
   │
   ▼
最小解析器 ──► 规范事件 events.jsonl
   │
   ▼
状态归约器 ──► 周期/边界快照 snapshots.jsonl
   │
   └─────────► 对局摘要 summary.json

运行状态 ─────────────────────────────► WPF 界面
```

各层职责如下：

| 层 | 事实来源 | v0.1 责任 |
| --- | --- | --- |
| 日志跟随器 | `Power.log` 文件字节流 | 查找文件、跟随追加、处理停止信号并报告读取状态 |
| 原始证据 | 已读取的日志行 | 保存接收时间、来源路径和原文，供解析器升级后复核 |
| 规范事件 | 最小解析规则 | 把已识别行转换为带版本和顺序号的稳定记录；无法识别的内容保持未知 |
| 状态归约 | 当前对局的有序事件 | 维护 v0.1 已支持的阶段、回合和计数视图 |
| 持久化 | 会话及对局上下文 | 使用 JSONL 追加写入，并在对局结束或会话收尾时生成摘要 |
| WPF 界面 | 记录器状态通知 | 展示状态和错误，不改变游戏状态 |

## 4. 数据目录

默认应用数据根目录为：

```text
%LOCALAPPDATA%\HearthstoneAgent\
├── settings.json
└── sessions\
    └── {sessionId}\
        └── {matchId}\
            ├── raw-lines.jsonl
            ├── events.jsonl
            ├── snapshots.jsonl
            └── summary.json
```

- `sessionId` 表示一次记录器运行会话。
- `matchId` 是本地生成的对局标识，不等同于 Battle.net 或第三方平台 ID。
- `raw-lines.jsonl` 只在 `persistRawLines` 为 `true` 时创建；默认开启。
- 记录器从识别到 `CREATE_GAME` 的原始行开始保存当场证据，开始标记之前的普通日志行不进入对局目录。
- JSONL 文件一行一个完整 JSON 对象。进程意外退出时，最后一行可能不完整；读取端应忽略并报告该行，不能修造缺失事实。
- `summary.json` 是派生结果，可以重新生成，不应覆盖 JSONL 事实层。
- 文件字段和示例见 [记录格式](record-format.md)。

这些目录包含可能关联玩家名称、对局时间和本机路径的数据。默认只保存在当前 Windows 用户的本地应用数据中，不应提交到 Git 或公开分享。

## 5. 对局生命周期

### 启动和等待

记录器先读取本地设置，再尝试默认路径：

```text
%LOCALAPPDATA%\Blizzard\Hearthstone\Logs\Power.log
```

自动定位先检查固定默认路径；不存在时，会在 Hearthstone 的 `Logs` 目录中选择当时已经存在的最新候选。仍找不到时，应用保持运行并等待界面中显示的日志路径出现；这不是一场对局失败。用户选择或界面保存了显式路径后，记录器只跟随该路径，日志迁移到新的时间戳目录时需要重新自动定位或浏览选择。

### 开始记录

解析器观察到对局创建/开始证据后生成新的 `matchId` 和对局目录。后续记录使用当场单调递增的 `sequence`，相同原始行不能在同一对局中重复产生两份事实记录。

### 对局中

每个受支持事件按顺序写入 `events.jsonl`，随后更新内存状态。遇到创建游戏、回合/步骤/胜负标签、选择/options 边界、发送选项、对局完成和配置的事件间隔时写快照；结束收尾时还会补写尚未持久化的最后状态。快照用于快速查看，但它只是事件流的派生视图。遇到未知标签或无法解析的行时，记录器保留原始证据并避免用默认值伪装事实。

### 结束和异常退出

检测到受支持的对局结束证据时写入 `summary.json`。用户正常停止、检测到下一场游戏或记录循环发生可捕获错误时也会为活动对局收尾，并通过 `completionReason` 区分。如果操作系统强制结束进程或断电，最后摘要可能来不及创建。如果日志中断、应用退出或客户端崩溃，不能把缺失结果记作胜或负。

## 6. 顺序和时间约定

- 所有持久化时间使用 UTC ISO 8601 字符串。
- `sequence` 表示记录器观察到的对局内顺序，不能用多个日志时间戳替代。
- 日志中的游戏时间和本机接收时间是不同概念；字段缺失时保持 `null`。
- 原始行和规范事件通过来源行号或等价引用关联。
- 同一个 `matchId` 的已有 JSONL 内容只追加，不就地修改。
- 格式发生不兼容变化时提升 `schemaVersion`，旧文件保持可识别。

## 7. 隐私与安全边界

- v0.1 只读取用户明确配置或默认 Hearthstone 日志目录中的文件。
- 应用不会自动创建或修改 `log.config`；配置方法见 [Windows 接手说明](windows-handoff.md)。
- 应用不读取 Hearthstone 进程内存，不注入代码，也不发送游戏输入。
- 分享诊断记录前应检查玩家名、BattleTag、本机用户名、绝对路径和其他个人信息。
- 不要把 `%LOCALAPPDATA%\HearthstoneAgent` 下的真实运行数据加入仓库。

## 8. 已知限制

- Blizzard 可随客户端补丁改变日志文本、标签或目录结构，v0.1 不保证自动兼容未来版本。
- 当前解析器只覆盖最小事件集合；文件中出现原始行不代表一定会产生规范事件。
- 只看到公开信息和己方日志可见信息，不能确定对手未公开手牌或牌库。
- 裸玩家名标签需要日志此前提供名称与实体 ID/玩家 ID 的关联；Windows 首测必须核对 `CURRENT_PLAYER` 和 `PLAYSTATE`。
- 识别到终局后会立即关闭当场 writer，紧随其后的少量终局尾部日志不会写入该场记录。
- 当前每个规范事件都会生成完整内存快照；长局或手动回读历史内容时需要观察内存、GC 和界面延迟。
- 日志首次打开位置、文件截断和轮转语义需要在 Windows 实机确认。
- 默认 `readExistingLogOnStart` 为 `false`，只监听启动后的新增内容；手动启用回读会生成新的本地记录，且历史摘要的观察时长不等于真实对局时长。
- 显式路径不存在、指向目录或暂时不可访问时，v0.1 的状态提示可能无法准确区分原因。
- 使用显式日志路径时不会自动切换到另一个新建的时间戳日志目录。
- 系统休眠、磁盘空间不足、杀毒软件锁文件和权限问题尚未完成实机验证。
- JSONL 目前面向本地调试，未提供压缩、索引、迁移或长期保留管理。
- v0.1 已通过 .NET 8 Windows 交叉目标 Release 编译，但尚未执行 Windows/Hearthstone 人工测试；交付时提供待执行清单。

先完成 [Windows 人工交接清单](windows-handoff.md#7-人工测试清单)，保存应用版本、Hearthstone 构建、Windows 版本、客户端语言和每项结果。发现解析差异时优先保留脱敏的最小日志片段和对应 UI 时间线，再修改解析规则。
