# 领域与数据模型

## 1. 建模目标

数据模型需要同时表达三类信息：

- 已经从可靠事件确认的事实。
- 通过画面或规则推断但仍有不确定性的状态。
- 对隐藏信息的概率分布，例如对手卡组和可能持有的响应牌。

这三类信息不能混为一个布尔值。所有推断都应保留依据和置信度。

## 2. 核心不变量

1. 一场对局中的规范化事件按 `sequence` 单调递增且不可修改。
2. 任意状态快照都可以由指定事件位置和版本化规则重建。
3. 卡牌定义 `CardDefinition` 与对局中的卡牌实例 `CardInstance` 分离。
4. 已公开事实、规则推导和概率推断分别存储。
5. 未知值保持未知，不使用默认值伪装成已知状态。
6. 生成、偷取、复制、发现、变形和洗入牌必须保留来源链。
7. 历史对局永远引用当时的数据快照，新的平衡补丁不能改变旧对局含义。
8. 聚合报告可以从事实记录重新生成，不作为唯一事实来源。

## 3. 标识与版本

| 字段 | 用途 |
| --- | --- |
| `matchId` | 本地生成的一场对局标识 |
| `gameEntityId` | 客户端日志中的临时实体标识，仅在当场有效 |
| `cardId` | 卡牌数据源提供的稳定定义标识 |
| `cardInstanceId` | 本地的卡牌实例标识，关联实体及来源链 |
| `sequence` | 对局事件的严格顺序 |
| `stateVersion` | 每次状态归约后的版本号 |
| `gameBuild` | 客户端构建或补丁标识 |
| `cardSnapshotId` | 卡牌定义数据快照 |
| `ruleSetId` | 规则解释与效果标签版本 |
| `metaSnapshotId` | 指定模式、地区、分段和日期的环境快照 |
| `decisionPolicyId` | 决策权重、提示模板和模型配置组合版本 |

## 4. 事件模型

### 4.1 GameEvent 信封

每个规范事件包含：

- 事件类型和模式版本。
- `matchId`、`sequence`、UTC 时间及可用的游戏内时间。
- 原始来源：日志、画面、用户输入或规则推导。
- 来源位置，例如日志文件偏移或画面帧标识。
- 置信度和解析告警。
- 涉及的实体、玩家、区域和变更值。
- 对应的游戏构建号及规则版本。

### 4.2 主要事件类别

- 生命周期：对局发现、开始、阶段变化、回合开始、回合结束、对局结束。
- 实体：创建、显示、隐藏、销毁、变形、控制权变化。
- 区域：牌库、手牌、战场、坟场、移除区等区域迁移。
- 属性：攻击、生命、费用、伤害、沉默、冻结、攻击次数、附魔变化。
- 动作：出牌、攻击、英雄技能、触发、选择、发现、目标指定。
- 资源：法力、临时法力、护甲、疲劳、过载或其他版本化资源。
- 诊断：日志缺口、乱序、未知标签、画面冲突、重新同步。

原始日志内容不直接进入核心决策；必须先转换成稳定、可测试的规范事件。

## 5. 对局状态模型

### 5.1 GameState

`GameState` 是指定 `stateVersion` 的不可变视图，包含：

- 对局阶段、模式、回合号、当前行动方和剩余时间估计。
- 先手玩家、后手玩家及硬币来源。
- 双方 `PlayerState`。
- 全部公开实体和己方可见的私有实体。
- 当前选择、目标、发现、换牌等交互上下文。
- 已知的合法动作基础条件。
- 事件完整性、关键字段置信度和暂停原因。

### 5.2 PlayerState

- 英雄、英雄技能、生命、护甲及状态。
- 当前和最大资源、临时资源及版本特定资源。
- 武器、地点、任务、奥秘等区域。
- 手牌数量；己方保存完整可见实例，对方只保存已确认信息。
- 初始牌库、已知剩余牌库、多重集合及疲劳状态。
- 战场顺序、随从状态、附魔和可攻击信息。
- 已使用卡牌、已触发效果及公开历史摘要。

### 5.3 CardInstance

一个实例至少包含：

- `cardId`，未知时允许为空。
- 当前控制者、所有者、区域和区域位置。
- 当前费用、攻击、生命和其他可变属性。
- 已知附魔、沉默、伤害、冻结和攻击状态。
- 可见性及最后确认时间。
- 来源类型与父实例，例如 `StartingDeck`、`Generated`、`Discovered`、`Copied`、`Stolen`、`Transformed`、`Shuffled`。
- 创建该实例的事件和完整来源链。

来源链是记牌和对手卡组推断的关键。只有可信的 `StartingDeck` 证据才能作为强卡组证据。

## 6. 卡牌知识模型

### 6.1 CardDefinition

- 卡牌稳定 ID、数据库 ID和收藏属性。
- 多语言名称与文本。
- 类型、职业集合、费用、攻击、生命、耐久等基础属性。
- 扩展包、稀有度、种族、法术学派和关键词。
- 可用模式、收藏状态和补丁有效区间。
- 原始数据来源、同步时间和校验摘要。

### 6.2 EffectTag

结构化效果标签用于快速搜索和启发式评估，例如：

- 伤害、治疗、抽牌、发现、召唤、变形、沉默、冻结。
- 单体或范围、友方或敌方、是否需要目标。
- 最小值、最大值、条件、随机性和潜在分支数。
- 对手回合响应、持续效果、亡语或触发时机。

标签不是完整游戏规则引擎。无法可靠结构化的复杂效果保留原始文本，并标记规则覆盖级别。

### 6.3 CardRelationship

描述主卡与衍生物、英雄技能、召唤物、变形结果、附属卡组或其他关联实体。关系记录有效补丁范围，不能假设永远不变。

## 7. 卡组与环境模型

### 7.1 DeckDefinition

- 卡组名称、模式、职业集合、卡组代码及规范化哈希。
- 主卡组和附属卡组的卡牌多重集合。
- 创建来源、导入时间和适用补丁。
- 用户标签以及是否是当前受支持的己方卡组。

### 7.2 MetaSnapshot

表示一次不可变的环境数据快照：

- 数据源和使用条款标识。
- 抓取时间、覆盖时间、游戏补丁。
- 模式、地区、排名区间和样本量。
- 抓取状态、校验结果和陈旧时间。

### 7.3 DeckArchetype 与 Variant

原型表示策略层面的卡组簇，变体表示具体构筑。至少保存：

- 原型名称、职业、核心策略和签名卡。
- 每张牌在该原型中的采用率和常见数量。
- 变体卡表、规范化哈希及来源。
- 使用率、胜率、样本量及其统计区间。

不能把单一网站的一套卡表视为原型的完整定义。

## 8. 对手模型

### 8.1 OpponentHypothesisSet

每次有效证据后保存一个候选集合：

- 候选原型或变体 ID。
- 先验概率、当前后验概率和相对排序。
- 支持证据、冲突证据及其权重。
- 可能仍在牌库或手牌中的关键卡概率。
- 快照时间、状态版本和计算方法版本。
- `Unknown` 质量，用于表达所有已知原型都解释不好的概率。

### 8.2 UnknownDeckObservation

非主流卡组记录包含：

- 职业、模式、补丁和排名范围。
- 确认来自原始构筑的公开卡牌。
- 排除生成牌后的卡牌签名。
- 与最近原型的相似度及低置信原因。
- 对局结果和人工复核状态。

未知样本按补丁隔离，不能跨版本直接聚类。

## 9. 动作与决策模型

### 9.1 GameAction

高层动作类型包括：

- 保留或替换起始手牌。
- 打出卡牌并指定目标及位置。
- 使用英雄技能并指定目标。
- 使用随从或英雄攻击。
- 选择发现或其他选项。
- 结束回合、取消当前交互或安全暂停。

每个动作包含前置状态版本、执行主体、目标、消耗、预期事件和合法性证明摘要。

### 9.2 ActionSequence

动作序列保存：

- 有序动作列表。
- 每一步后的预测状态。
- 确定性结果、随机结果分支及概率。
- 总时间预算、搜索深度和剪枝原因。
- 战术评分、风险评分和最终综合值。

### 9.3 DecisionRecord

- 决策类型和使用的状态版本。
- 候选序列及各评分分量。
- 对手假设集合摘要。
- 是否调用模型、模型配置引用、耗时和用量。
- 模型返回的结构化选择及验证结果。
- 最终决定、执行模式和人类是否确认。
- 结果状态、偏差和复盘标签。

模型完整原始响应可以按诊断策略短期保存，但统计只引用脱敏摘要。

## 10. 执行与结果模型

`ExecutionAttempt` 记录单个高层动作的一次执行：

- 动作、窗口身份、校准配置和执行器版本。
- 前置条件检查结果。
- 输入步骤及时间，但不保存与目标无关的全局输入。
- 预期与实际事件。
- 成功、超时、用户取消、失焦或状态漂移结果。
- 是否触发暂停和相关诊断证据。

执行重试必须产生新 Attempt，不覆盖失败记录。

## 11. 对局与报告模型

### 11.1 MatchRecord

- 开始和结束时间、模式、地区、补丁。
- 己方卡组定义及实际英雄。
- 对手职业、最终原型分布和识别置信度。
- 先后手、结果、结束原因、回合数和时长。
- 运行模式变化、人工接管、异常和掉线。
- 排名变化；无法可靠读取时保持未知。

### 11.2 DailyReport

日报由 MatchRecord 和事实事件派生，包含：

- 总对局、胜负、异常终止及总体胜率。
- 职业、原型、先后手、卡组版本维度的样本与胜率。
- 平均/中位对局时长和回合数。
- 对手识别置信度分布及未知卡组列表。
- 决策耗时、模型失败率、执行失败率和费用估算。

对每个胜率同时显示样本数；低样本量使用置信区间或明确提示。

## 12. 数据保留与删除

- 卡牌和环境快照长期保留，因为历史对局依赖它们。
- 规范事件和决策摘要按用户设置保留。
- 原始日志片段和截图采用更短保留期，默认不保存完整屏幕录像。
- 用户可以按对局或日期清除原始诊断数据，同时保留匿名聚合。
- 数据库删除需要处理关联，但不得留下看似完整、实际缺少依据的决策记录。
